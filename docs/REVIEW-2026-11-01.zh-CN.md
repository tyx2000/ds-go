### SCOR-027 — 自动唤醒回合无法接管空闲聊天输入

- lane: code/errors；scope: pre-existing，裁剪后仍可达。
- affected_files: [cli.go:715](/Users/adib/Documents/ChatGPT/ds-go/internal/cli/cli.go:715)、[cli.go:568](/Users/adib/Documents/ChatGPT/ds-go/internal/cli/cli.go:568)、[questions.go:67](/Users/adib/Documents/ChatGPT/ds-go/internal/cli/questions.go:67)。

- reliable_solution: 给输入 broker 建立明确的 composer/交互所有权交接：挂起或取消普通读取后再展示问题，或明确暂停自动回合并提示用户接手；不能只删互斥锁让两个 reader 抢 stdin。交接、取消与迟到答案必须保持隔离。
- solution_fit: suited=yes，沿用现有输入 broker；executable=yes；affordable=yes；cost=medium，包含输入生命周期和 PTY/pipe 回归；verification=后台通知唤醒根模型提问时，无额外普通输入即可显示问题并回答。
- baseline_verification_result: failed；`TestReviewAutomaticQuestionCanTakeOverIdleChatPrompt` 用真实 chat + io.Pipe + manager wake，已确认模型到达 tool_started 后问题仍不能显示；清理关闭 pipe 并取消，无遗留进程。
- fix_outcome: implemented; verification_result: passed.
- suggested_tests: 问答与审批两条链；空闲 composer、续行、取消及迟到输入；前台交互和无人工交互 run/JSON 的拒绝语义不得退化。

### SCOR-028 — one-shot run 的自动收尾失败仍返回成功

- severity: P2；status: fixed；issue_evidence: confirmed。
- lane: errors/code；scope: pre-existing。
- affected_files: [subagent_contract.go:663](/Users/adib/Documents/ChatGPT/ds-go/internal/cli/subagent_contract.go:663)、同文件 795–825、885；[cli.go:338](/Users/adib/Documents/ChatGPT/ds-go/internal/cli/cli.go:338)。
- failure_scenario: 初始回合成功启动后台工作并结束；job 完成通知自动唤醒根会话收集结果，该次模型请求失败。wake goroutine 只打印错误，settle 只等忙闲和资源状态，不保留自动根回合的失败结果。
- impact: `settleDelegations()` 返回 nil，Main 返回 0，尽管日志已经持久记下 failed turn。调用脚本无法通过退出码判断任务没有完成，收到的可能只是初始“等待后台结果”的回答。
- reliable_solution: 按 root/activation 保存自动收尾结果，并在 one-shot settle 后传播尚未处理的根失败。不要把子代理失败直接等同整个任务失败：子代理失败本应仍可由父模型处理和恢复。
- solution_fit: suited=yes，沿用 manager 的 wake ownership；executable=yes；affordable=yes；cost=medium，需确定错误汇总与恢复边界；verification=初始成功、自动根请求失败时最终返回非 nil/非零，成功处理子失败的父回合仍可成功。
- baseline_verification_result: failed；`TestReviewOneShotSettlementReportsAutomaticTurnFailure` 观察到 durable `turn/finished` 为 failed，错误 `REVIEW_BACKGROUND_COLLECTION_FAILED`，但 Main(run) 所用的 settleDelegations 返回 nil。退出码结论由 Main 的直接分支成立。
- fix_outcome: implemented; verification_result: passed.
- suggested_tests: 自动根模型失败、预算耗尽、取消、重试后成功、多个通知合批，以及父模型成功处理子失败。

### SCOR-029 — 前台超时转后台与结算竞争会漏掉完成通知

- severity: P2；status: fixed；issue_evidence: confirmed。
- lane: code/errors；scope: pre-existing。
- affected_files: [standard_bash.go:506](/Users/adib/Documents/ChatGPT/ds-go/internal/tools/standard_bash.go:506)、同文件 581、627、890。
- failure_scenario: timer 分支已选中，但前台尚未锁住 job 并减少 waiter；进程结算先得到 job 锁，捕获 `awaited=true` 并关闭 done。随后前台返回 promoted，settlement 又依据旧 awaited 抑制通知。done 和 timer 同时 ready 也可形成同类交错。
- impact: 模型收到“仍运行、已转后台、结束会通知”的结果，但实际上任务已经结束且不会再通知。自动收集链断开，one-shot 可以退出；手动 job_output 仍能取回输出。
- reliable_solution: 在 timeout 分支锁内检查是否已经结算；已完成则交付 foreground 终态并移除记录，否则原子完成 foreground waiter → background 的交接，和结算的通知判定保持一致。
- solution_fit: suited=yes，改动限于现有交接边界；executable=yes；affordable=yes；cost=low/medium；verification=任意边界时序下满足二选一：foreground 已完整交付，或 promoted 且收到恰好一次通知。
- baseline_verification_result: failed；`TestReviewPromotedJobCannotLoseCompletionNotice` 用真实短 bash 命令及受控 job 锁时序复现：返回 promoted、output 已是 completed，noticed 已关闭却通知数为零。不是只凭压力测试猜测，未估计自然发生频率。
- fix_outcome: implemented; verification_result: passed.
- suggested_tests: timer 与 done 同时 ready、timer 选择到 waiter 减少之间结算、正常前台/后台、主动 kill 和被等待释放的通知抑制。

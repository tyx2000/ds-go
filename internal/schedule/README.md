# Schedule port status

Baseline: [official Schedule service at `687f282e8625c6b8d11ff58211a90524be2e4317`](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/schedule/schedule/README.md).

The current Go service stores one-shot, fixed-rate, daily, weekly, and five-field cron reminders in an atomic JSON document. It validates the whole document on open, preserves committed UTC targets on restart, and records a stable pending delivery id before calling the delivery consumer. The consumer must deduplicate that id against durable Session events; scheduler and Session storage are separate transactions.

The terminal Host uses `RunBatchesWithStart`. It acquires the daemon lock before recovery, admits deliveries in storage order, and shares a FIFO operation slot with task mutations. Another Session's delivery cannot overtake a blocked restoration. An advisory operation lock also serializes management from another dsgo process; reads remain available. Shutdown cancels admission and waits for its callback to release the slot. The old single-task `RunWithStart`/`tick` path remains for saved dsgo integrations; it is not the Host path used by `dsgo daemon`.

The callback acknowledges durable inbox acceptance, **not model execution**. One-shot reminders get individual messages. Every due recurring reminder in the same Session contributes its latest occurrence to one `[SCHEDULE REMINDER BATCH]` message. Both forms use the official framing and `source.kind: schedule`. The CLI persists Inbox input before recording receipts and uses `ContinueInbox` to wake it after any busy turn, with daemon lifetime owning the model work. Recovery also wakes scheduled input that was persisted but never admitted to a turn.

The Host arms the nearest future obligation, with the official maximum timer delay. A failed restoration, enqueue or receipt commit does not get an automatic retry timer. A later management mutation, another scheduled wake or restart can retry it. A lightweight file metadata watcher detects management performed by another terminal process; unchanged failed tasks are not retried on watcher ticks. Successful members of a partially acknowledged batch keep their future timer obligations.

Recurring catch-up selects the most recent due occurrence instead of replaying every missed occurrence. Daily and cron timing skip missing local times and select only the earlier instant of an overlap, including half-hour transitions. Cron uses the Vixie day-field rule: a field beginning with `*` keeps the day conjunction even when it is stepped. Numeric expansion rejects unsupported spellings and handles very large steps without integer overflow. Fixed intervals keep creation alignment even across time spans beyond `time.Duration` subtraction limits.

The official API adapter provides `CreateOfficial`, `ListOfficial`, `GetRecord`, `UpdateOfficial`, `DeleteOfficial`, `Catalog`, `History`, and `StopSession`. Its six creation selectors require an explicit title; title validation counts UTF-16 units like the upstream JavaScript implementation. Daily/weekly times normalize to millisecond precision, weekly rules keep unique ascending ISO weekdays, and cron canonicalization preserves leading-star flags and searches the 400-year Gregorian date cycle. `DecodeCreate`/`DecodeUpdate` validate exact model-tool keys and safe-integer numeric semantics. `ToolSpecs` exposes the official four names: `schedule_create`, `schedule_list`, `schedule_update`, `schedule_delete`.

Updates compare the entire observed canonical Record inside the writer lock. Equivalent timing keeps its committed target, while a timing change re-anchors without replacing identity or saved history. Physical deletion removes both the task and its history. `SetOptions.CheckSession` supplies the Host admission guard for create/update; the calling tool executor must separately refuse all four reminder tools for delegated callers. Archive callers use the active list to refuse archive, or explicitly call `StopSession` to remove active reminders.

After durable Session admission, the consumer calls `AcknowledgeBatch` with the actual persisted Inbox event identity. Members share that message id and acceptance timestamp; each receipt, sent-prompt snapshot, committed next target and retention change is written separately, matching partial-commit recovery. A later legacy callback settlement sees the cleared pending id and cannot advance twice. Defaults retain 30 days and 200 records per task; history reads are newest-first in append order, support exclusive message-id cursors, and distinguish unavailable older records from confirmed pruning. A callback without a real message identity never fabricates a receipt.

New wall-clock inputs use an embedded canonical-name table generated with the official `Intl.DateTimeFormat(...).resolvedOptions().timeZone` algorithm over supported IANA names; generation records Node, ICU and tzdata versions. This includes case-insensitive names and aliases such as `US/Eastern`. Stored valid aliases and already committed UTC targets are not rewritten when reopening. Go's installed IANA database still owns recurrence arithmetic. `generate_zones.py` updates name data; ordinary Go reminder execution does not invoke Node.

Model-tool failures return the official ordinary `{code,message}` JSON values. Delegated callers receive `subagent_session`; storage and internal failures collapse to `internal_error` without storage details. The service still lets a human remove historical tasks bound to a delegated Session. Create captures its relative-time anchor before waiting in the Host FIFO.

Existing dsgo task rows remain readable without read-time rewrites. Migrating an unnamed legacy row through the official editor requires an explicit title; a name is never derived from its instruction. The old `Create`/`List`/`Cancel` APIs remain available for the initial dsgo format, and `Cancel` retains an inactive row. This does not imply compatibility with the upstream Host's different JSON domain layout.

This is not full official Schedule parity. Remaining differences include:

- Time-zone canonical-name data is a recorded ICU snapshot; a Host with different ICU or IANA data can differ for recently changed zones. Targets remain subject to the installed Go IANA database.
- Host Session-controller restoration is reconstructed with the terminal Engine and durable Inbox. No complete Web-controller same-input differential has been run.
- Enqueue and task receipts are separate transactions. Partial writes or process death can repeat delivery, as the official Host also documents; neither runtime claims exactly-once cross-store delivery.
- The supported locking backends are macOS/Linux/FreeBSD. Other platforms fail explicitly.

Tests cover recurring batches and shared receipts, partial acknowledgment timers, Host FIFO delivery/management, failed-admission retry boundaries, alias canonicalization, busy-session queueing and unadmitted Inbox recovery, alongside recurrence/DST/cron, strict inputs, CAS, history retention, ownership, deletion and legacy-runtime regressions.

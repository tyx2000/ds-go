# Schedule port status

Baseline: [official Schedule service at `687f282e8625c6b8d11ff58211a90524be2e4317`](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/schedule/schedule/README.md).

The current Go service stores one-shot, fixed-rate, daily, weekly, and five-field cron reminders in an atomic JSON document. It validates the whole document on open, preserves committed UTC targets on restart, and records a stable pending delivery id before calling the delivery consumer. The consumer must deduplicate that id against durable Session events; scheduler and Session storage are separate transactions.

`RunWithStart` acquires the process-wide daemon lock before invoking recovery. Daemon shutdown cancels admission callbacks and waits for accepted scheduler work to settle. Advisory file locks leave no stale ownership after process death. Callbacks for different Sessions can proceed concurrently; callbacks for the same Session are serialized. A later timer can admit another Session while a previous callback is blocked restoring its Session. A second scheduler/Store rechecks committed task state and cannot concurrently admit the same task.

The callback acknowledges durable inbox acceptance, **not model execution**. Its context belongs to the admission attempt and ends when the callback returns. After acceptance, the daemon or agent manager must own any continuing model turn. Cancellation prevents a queued callback from being admitted, cancels a local in-flight admission immediately, and is observed from another Store/process within the admission polling interval. Already accepted Session messages remain durable.

Recurring catch-up selects the most recent due occurrence instead of replaying every missed occurrence. Daily and cron timing skip missing local times and select only the earlier instant of an overlap, including half-hour transitions. Cron uses the Vixie day-field rule: a field beginning with `*` keeps the day conjunction even when it is stepped. Numeric expansion rejects unsupported spellings and handles very large steps without integer overflow. Fixed intervals keep creation alignment even across time spans beyond `time.Duration` subtraction limits.

The official API adapter provides `CreateOfficial`, `ListOfficial`, `GetRecord`, `UpdateOfficial`, `DeleteOfficial`, `Catalog`, `History`, and `StopSession`. Its six creation selectors require an explicit title; title validation counts UTF-16 units like the upstream JavaScript implementation. Daily/weekly times normalize to millisecond precision, weekly rules keep unique ascending ISO weekdays, and cron canonicalization preserves leading-star flags and searches the 400-year Gregorian date cycle. `DecodeCreate`/`DecodeUpdate` validate exact model-tool keys and safe-integer numeric semantics. `ToolSpecs` exposes the official four names: `schedule_create`, `schedule_list`, `schedule_update`, `schedule_delete`.

Updates compare the entire observed canonical Record inside the writer lock. Equivalent timing keeps its committed target, while a timing change re-anchors without replacing identity or saved history. Physical deletion removes both the task and its history. `SetOptions.CheckSession` supplies the Host admission guard for create/update; the calling tool executor must separately refuse all four reminder tools for delegated callers. Archive callers use the active list to refuse archive, or explicitly call `StopSession` to remove active reminders.

After durable Session admission, the consumer calls `Acknowledge` with the actual persisted user-message identity. This writes the receipt, immutable sent-prompt snapshot, next target, and history retention as one task-store transaction. A later legacy callback settlement sees the cleared pending id and cannot advance twice. Defaults retain 30 days and 200 records per task; history reads are newest-first in append order, support exclusive message-id cursors, and distinguish unavailable older records from confirmed pruning. A legacy callback without a real message identity never fabricates a receipt.

Existing dsgo task rows remain readable without read-time rewrites. Migrating an unnamed legacy row through the official editor requires an explicit title; a name is never derived from its instruction. The old `Create`/`List`/`Cancel` APIs remain available for the initial dsgo format, and `Cancel` retains an inactive row. This does not imply compatibility with the upstream Host's different JSON domain layout.

This is not full official Schedule parity. Remaining differences include:

- Same-Session recurring reminders are delivered sequentially, rather than combined into the official recurring reminder batch message.
- This runtime samples the clock every second and retries failed pending admissions on later samples. The official runtime does not schedule an automatic retry timer after a failure; only later management, another wake, or restart retries it.
- IANA alias canonicalization is currently limited to Go's installed zone names and UTC aliases. Full ICU/Temporal canonical-name parity is not established, and targets remain subject to the installed IANA database.
- A claimed pending occurrence retains its immutable instruction across a concurrent content edit or retry; the edited instruction applies to future occurrences. Full FIFO ordering against the original Host's delivery/controller implementation has not been differentially verified.
- The supported locking backends are macOS/Linux/FreeBSD. Other platforms fail explicitly.

The tests cover latest missed occurrences, stable pending ids after restart, overlap/gap timing, cron day rules and canonicalization, century leap timing, strict official inputs, complete-record CAS, no-op and changed timing, receipt idempotence, prompt snapshots, history retention/pagination, physical deletion, explicit legacy migration, delegated admission, archive cleanup, cross-Store cancellation, overlapping tick ownership, Session serialization, independent Session progress, lock-before-recovery ordering, corrupt-store preservation, and daemon shutdown/restart.

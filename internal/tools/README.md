# Built-in tools

This package is a fixed Go implementation, not a plugin loader. The source baseline is DeepSeek Harness commit `687f282e8625c6b8d11ff58211a90524be2e4317`:

- [Tool execution and PTC presentation](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/core/tools/README.md)
- [Node PTC runtime](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/ptc-runtime/ptc-runtime-node/README.md)
- [Sandbox behavior](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/docs/subsystems/sandbox.md)

`New()` registers `read_file`, `write_file`, `edit_file`, `list_directory`, `search_files`, `bash`, `run_shell`, `jobs`, `terminal`, `run_code`, the official `read`/`write`/`edit`, `standard_bash`, `job_output`, `job_list` and `job_kill`. `Register(core.ToolSpec, Handler)` adds the other fixed application modules. Every native or nested PTC call passes through the same validation, context, and handler. The application persists the outer tool call/result; nested calls emit `tool/subcall` and `tool/subresult` for persistence by `ToolContext.Emit`.

## Files and permissions

Read offsets are zero-based lines. Text files are capped at 16 MiB and one rendered result at 1 MiB. Binary and invalid UTF-8 input is rejected. Search does not traverse symbolic links, `.git`, or `node_modules`. Writes use an `os.Root` directory handle and a synced temporary file followed by confined rename; this needs Go 1.25. Target symlinks are rejected. Ambiguous exact edits require `replace_all`.

`read-only` writes and workspace writes outside the canonical workspace ask once. `never`, no approval channel, denial, canceled approval, or a late allow after cancellation all refuse execution. A grant changes only that invocation. Arbitrary shell/Node programs use actual OS filesystem enforcement: macOS Seatbelt (`sandbox-exec`) or Linux bubblewrap. An unavailable backend fails closed; there is no implicit full-access retry. `full-access` selects ordinary host access deliberately.

The sandbox reports filesystem enforcement. It does not claim network isolation. Process cancellation and completion kill the process group; children that deliberately create a new session are a remaining cleanup limitation. Windows restricted execution and PTY are not implemented. macOS enforcement has a real integration test requiring execution outside a surrounding sandbox that forbids nested sandbox creation. Linux bubblewrap needs a separate Linux integration run.

## Shell, jobs, and PTY

`standard_bash` is the official standard-preset `bash` ([tool-bash](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/shell/tool-bash/README.md)); the application advertises it as `bash` outside the minimal preset, whose `bash` is the persistent shell. Each call is a fresh `bash -c` with `NO_COLOR=1 TERM=dumb PAGER=cat GIT_PAGER=cat`. Every command is a `bash-<16 hex>` job from its start: `run_in_background` returns the id at once, a foreground command that outlives `timeoutMs` (default 120000, clamped to 600000) keeps running and its result carries one consuming read, and a foreground command that settles in time leaves the registry with its result. Each stream keeps a 64,000-byte tail; after the first overflow the complete stream, up to 64 MiB, goes to a private file under `SetSpillDir`. Values are canonical JSON; `RenderShellResult` produces the official model text: stdout, one `[stderr]` section, then sandbox, `[stopped: …]`, signal or nonzero exit markers. Denials are inferred from a failed run's stderr in the backend's dialect. `sandbox_permissions` follows the official escalation rules: repeating the effective mode needs nothing, a strictly wider mode needs a justification and approval, a narrower one fails. `job_output`, `job_list` and `job_kill` ([tool-jobs](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/jobs/tool-jobs/README.md)) serve every job kind with a single model cursor; waits default to 30 s and clamp to 600 s. When an owned bash job settles, `SetJobNotifier` receives the official notice `background job <id> (<kind>: <label>) finished [status: …]. Read its output with job_output.`; the application delivers it to the owning Session's inbox, which a busy agent admits at its next step and which wakes an idle one. A settlement that released a live wait (the foreground call's own wait, `job_output` with `wait: true`, or a `jobs` wait), a kill the model requested through `job_kill`, and registry teardown send none; a stop through `/jobs` does notify. `HasPendingJobs` reports jobs whose notice is not handed over yet, so a one-shot run can wait for them. The `jobs` tool and `/jobs` still observe these jobs through `legacySnapshot`.

`run_shell` deadlines default to 120 seconds with a 600-second ceiling. Captured output is bounded to 1 MiB. `background: true` returns an owner-scoped process-local job. `jobs` supports `list`, `output`, `wait`, and `kill`; observers do not advance the model's output cursor unless `consume: true` is supplied. Process-local jobs do not resume after dsgo exits.

`terminal` starts a real controlling PTY using [creack/pty v1.1.24](https://github.com/creack/pty/tree/v1.1.24). It supports exact input/control characters, size changes, output offsets, read waits, and owner-scoped cancellation. PTY output uses the same 1 MiB capture limit. A resize/echo/interactive read/cancel test exercises a real PTY.

Harness credential environment variables are removed from shell, PTY, and Node children: names containing `KEY`, `PASSWORD`, `SECRET`, or `TOKEN`, and names prefixed with `DSH_` or `DSGO_`. This filters inherited environment variables; it is not a promise that ordinary filesystem-readable files are secret from model code.

## TypeScript PTC

Node.js 22.13 or newer must provide `node:module.stripTypeScriptTypes`. `SetNodePath(path)` selects the executable; empty means `node` on PATH. Control messages use inherited fd 3, separate from captured stdout/stderr. Runtime limits are 512 MiB V8 old-generation heap, 1 MiB output, 16 MiB control frame, and 10 overlapping host bindings. Output overflow terminates the runtime. Tool exceptions are model-visible tool failures.

`SetPTCMode("per-call")` is the default: each evaluation is an async function body with top-level `await` and `return`, with a fresh process and process-group cleanup on settlement.

`SetPTCMode("persistent-in-memory")` retains a Node REPL per session owner. Top-level declarations and dynamic imports persist; top-level `await` and a final JSON expression work, while top-level `return` does not. Redeclaration follows Node REPL behavior. Evaluations for the same owner cannot overlap. A normal program exception preserves earlier mutations. Cancellation, timeout, output overflow, process exit, cwd/policy changes, and `InvalidateSession(id)` release memory. A once-approved broader sandbox runs in a separate per-call process. Retained callbacks may call tools only during their originating evaluation; saved tool methods invoked in a new evaluation use that evaluation's context.

The persistent runtime requires Node's REPL domain interface to settle thrown exceptions. The implementation checks its existence at startup; compatibility is tested on local Node 24.22.1. Retained state is never saved or copied into forked sessions. The application must call `InvalidateSession` when changing standing permissions or closing a session. `PTCInstructions()` generates the runtime-specific model instructions and the current tools SDK/schema contract.

These are tested Go behaviors. They have not yet been compared against every official tool schema, presentation transform, or lifecycle fixture, so this package alone does not establish complete Web parity.
